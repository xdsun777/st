## 1. 项目概述

### 1.1 项目目标

实现移动端优先的沉浸式刷题工具：数据本地存储，**默认零网络请求**；完成题库管理、刷题、错题复习、统计、备份恢复闭环；提供浅色/深色双主题与无边框沉浸式体验；可选接入 AI 判题与解析（用户自备 OpenAI 兼容 API）。

### 1.2 业务约束

1. 无账号、无登录、无服务端，所有数据本地存储
2. 支持 CSV/Excel 导入题库（字段一致）；自定义格式备份包，不与CSV/Excel互通
3. 题型：single单选、multi多选、judge判断、essay简答、fill填空；填空支持机器判分+人工覆写；essay 支持 AI 判分（可选）+人工覆写
4. 高危操作（删除题库、恢复备份）必须二次确认弹窗
5. **网络约束**：仅当用户配置 AI 并开启对应开关后，向用户指定的 Base URL 发起答题相关请求；其余场景零网络
6. 主题：浅色/深色/跟随系统三态，全局组件双主题适配

### 1.3 运行目标平台

- Windows `.exe`
- Linux `AppImage`
- Android `.apk`（自用，不发布应用商店；移动端为第一优先体验）

## 2. 整体技术选型

|层级|技术|版本建议|用途|
|---|---|---|---|
|应用外壳|Tauri 2.0|最新稳定版|Rust内核，跨平台，访问文件系统、SQLite、发起AI请求；输出桌面与Android包|
|前端框架|Vue3 + TypeScript|^3.5|页面组件、交互、刷题UI|
|UI样式|Tailwind CSS|^3 + CSS 变量|页面样式，双主题（dark class 策略）|
|状态管理|Pinia|^2|刷题会话、主题、设置、筛选条件内存状态|
|本地数据库|sqlx(SQLite)|0.8|Rust侧持久化全部业务数据（自管理连接池）|
|CSV解析|PapaParse|^5|前端解析CSV文件，字段校验，收集错误行|
|Excel解析|SheetJS(xlsx)|0.18|前端解析.xlsx/.xls，字段校验与CSV共用|
|文件系统|tauri-plugin-fs|内置|文件读取、导出备份包|
|HTTP客户端|前端 axios（浏览器 XHR/fetch，直连 API）|1.x|AI 调用|

> 排除方案
>
> 1. Electron：打包体积大，内存开销高
> 2. 纯Web/PWA：浏览器存储易丢失，文件访问受限
> 3. Flutter/Native：多端复用差，开发成本更高
> 4. 前端直接 fetch 调 AI：API Key 会暴露在前端 bundle/WebView 调试环境；**AI 请求统一走 Rust 层**，Key 仅存 Rust 侧数据库

## 3. 系统架构

> 分层：前端Web层（Vue3） ↔ Tauri Command ↔ Rust后端层（SQLite、文件IO、AI HTTP）

1. **Vue前端层**
   - UI渲染：题库列表、刷题页面、错题本、收藏、统计、设置、导入导出弹窗
   - 题库文件解析（CSV/Excel共用校验）、字段校验；填空判分字符串逻辑；表单输入；弹窗交互
   - 主题状态：Pinia 维护主题模式，通过 `dark` class + CSS 变量切换
   - 沉浸模式：进入刷题时切换布局（移动端隐藏导航）
   - 通过Tauri Command调用Rust能力，**不直接操作数据库、文件与网络**

2. **Rust后端层(Tauri Commands)**
   - SQLite数据库CRUD：题库集、题目、标签关联、做题记录、设置项、AI解析缓存
   - 文件IO：读取CSV/Excel文件、导出自定义备份包、恢复备份包
   - 聚合统计查询，大批量数据处理
   - **AI 调用**：前端 JS 读取完整 AI 配置（仅内存）→ axios 直连用户 Base URL 的 `/v1/chat/completions` 接口 → 解析结果 → 展示；判分结果通过 `update_ai_result` 命令写回数据库
   - 所有持久化操作统一在此层，前端只传参数

3. **数据流向**

```
前端UI → Tauri Command → Rust(SQLite / fs) → 本地磁盘
Rust查询结果 → 返回前端渲染

AI链路（仅AI功能开启时）：
前端提交essay/答错 → JS axios（浏览器 fetch）→ 用户配置的Base URL /v1/chat/completions
→ 解析JSON → 写入SQLite → 返回前端
```

> 网络约束：**默认零网络请求**；AI 功能关闭或未配置时，前端不构建 AI 客户端、不发送任何请求。

## 4. 数据库设计（SQLite）

> 在六张基础表基础上已实现扩展：answer_record 加 `ai_result` 列；新增 `settings`、`ai_analysis_cache` 两张表。

```sql
-- 题库集
CREATE TABLE question_bank (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  create_time INTEGER NOT NULL
);

-- 题目主表
CREATE TABLE question (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  bank_id INTEGER NOT NULL REFERENCES question_bank(id) ON DELETE CASCADE,
  q_type TEXT NOT NULL, -- single / multi / judge / essay / fill
  content TEXT NOT NULL, -- 题干
  options TEXT, -- JSON字符串存储选项，简答/填空为null
  answer TEXT NOT NULL, -- 答案；填空多答案英文分号;分隔
  analysis TEXT, -- 解析，可为null
  create_time INTEGER NOT NULL,
  update_time INTEGER NOT NULL
);

-- 标签
CREATE TABLE tag (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE
);

-- 题目-标签多对多关联
CREATE TABLE question_tag (
  question_id INTEGER NOT NULL REFERENCES question(id) ON DELETE CASCADE,
  tag_id INTEGER NOT NULL REFERENCES tag(id) ON DELETE CASCADE,
  PRIMARY KEY(question_id, tag_id)
);

-- 做题记录表：同时承载错题、收藏、作答记录
CREATE TABLE answer_record (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id INTEGER NOT NULL REFERENCES question(id) ON DELETE CASCADE,
  user_answer TEXT, -- 用户作答文本
  machine_result INTEGER, -- 0错误 1正确；essay为null
  ai_result INTEGER, -- AI判题结果 0错误 1正确；未启用AI时为null
  manual_result INTEGER, -- 人工覆写结果 null/0/1，优先级最高
  is_fault INTEGER NOT NULL DEFAULT 0, -- 是否错题 0否1是
  is_collect INTEGER NOT NULL DEFAULT 0, -- 是否收藏 0否1是
  fault_count INTEGER NOT NULL DEFAULT 0, -- 做错累计次数
  finish_time INTEGER NOT NULL
);

-- 刷题会话：保存中途退出的刷题进度
CREATE TABLE practice_session (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  bank_id INTEGER,
  tag_filter TEXT, -- JSON存储筛选标签/题集id序列
  current_index INTEGER NOT NULL DEFAULT 0,
  practice_mode TEXT NOT NULL, -- order / random
  create_time INTEGER NOT NULL
);

-- 设置项：key-value，存主题与AI配置
CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
-- 内置键：theme_mode(system|light|dark)、ai_base_url、ai_api_key、ai_model、
--         ai_judge_enabled(0|1)、ai_analysis_enabled(0|1)、encourage_enabled(0|1)

-- AI解析缓存：按 题目+作答哈希 缓存，避免重复调用计费
CREATE TABLE ai_analysis_cache (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id INTEGER NOT NULL REFERENCES question(id) ON DELETE CASCADE,
  answer_hash TEXT NOT NULL, -- 用户作答内容哈希（前端 djb2 计算）
  analysis TEXT NOT NULL, -- AI生成的错题解析
  create_time INTEGER NOT NULL,
  UNIQUE(question_id, answer_hash)
);
```

### 业务说明

1. `question.options` 使用JSON存储选项数组，例如`["A.xxx","B.xxx"]`
2. **最终结果解析顺序**：`manual_result` 不为 null 时最高；否则 `ai_result`；再否则 `machine_result`。统计与错题均以最终结果为准。
3. `ON DELETE CASCADE`：删除题库集自动删除题目；删除题目自动删除关联标签、做题记录、AI解析缓存
4. `practice_session`只保留一份有效会话，新建刷题时覆盖旧会话。
5. `settings` 读写封装为命令：`get_settings` / `set_setting`；`get_ai_config` 返回脱敏 Key 用于设置页展示；`get_ai_config_full` 返回完整 Key 仅供前端内存构建 axios 客户端（不落任何持久化存储）。
6. **迁移方案**：现有库通过 `ALTER TABLE answer_record ADD COLUMN ai_result INTEGER` 与新增表语句升级；启动时执行幂等迁移。

## 5. 模块技术实现细节

### 5.1 题库管理模块

1. **题库文件导入流程（CSV/Excel，字段规范一致）**
   1. 前端唤起文件选择，支持 `.csv` / `.xlsx` / `.xls`
   2. 按扩展名分支读取解析：
      - `.csv` → `readTextFile` 读文本 → PapaParse 解析
      - `.xlsx` / `.xls` → `readFile` 读二进制 → SheetJS 解析（取第一个工作表，第一行为表头，`raw:false` 统一转字符串）
   3. 两种格式产出相同结构的行对象数组，共用 `validateRows` 逐行校验：必填项、type枚举值合法性
   4. 收集错误行号+错误信息，不合法行直接跳过，UI展示错误汇总
   5. 将合法数据封装参数，调用Tauri Command传给Rust层批量写入SQLite（事务）
2. 单题CRUD：前端表单 → Tauri Command → SQLite增删改查
3. 题库集：新建、重命名、删除；删除前前端弹窗二次确认
4. 标签管理：新增、删除标签；给题目绑定/解绑标签；按标签ID筛选题目（Rust SQL查询）

### 5.2 刷题模块

1. 刷题模式：顺序 / 随机；随机在前端洗牌（保存题集id序列到 tag_filter，恢复会话时按序取题）
2. 会话保存：中途退出，把当前索引、筛选条件（含题集id序列）存入`practice_session`；再次进入可继续会话或重置会话
3. 题型处理
   - single/multi/judge：前端提交，Rust查询标准答案，前端判分渲染；答错标记`is_fault=1`，`fault_count+1`
   - fill填空：前端执行判分逻辑
     - 去除用户输入首尾空格；标准答案按`;`分割数组
     - **大小写敏感，中间空格不处理**，命中任意一个标准答案即机器判正确
     - 页面允许手动修改对错，写入`manual_result`字段，优先级最高
   - essay简答：无机器判分；**开启AI判题时**提交后调用 `ai_judge` 命令，写入`ai_result`；无论AI与否，均允许手动覆写`manual_result`
4. 提交答题后，生成一条`answer_record`记录存入数据库。
5. **沉浸模式**：移动端进入刷题后布局切换为全屏专注（隐藏顶栏/底部导航），退出刷题恢复。

### 5.3 错题 & 收藏模块

1. 错题本：查询"最终结果为错"的题目（SQL 用 `COALESCE(manual_result, ai_result, machine_result) = 0`），支持标签筛选；移出错题仅更新`is_fault=0`，**不删除做题记录**
2. 收藏：更新`answer_record.is_collect`；可单独刷收藏题目
3. 修改原题题干/答案：**不改动历史answer_record记录**。

### 5.4 统计模块

> 统计全部在Rust层通过SQL聚合计算，返回简单数值给前端渲染

- 全局统计：总刷题量、正确数、错误数、正确率
- 分题库统计：按bank_id分组统计
- 正确/错误口径：以最终结果（manual > ai > machine）统计；essay 未判题且未手动标记的记录不计入正确率分母
- 删除题目时，级联删除answer_record，统计数据自动同步更新。

### 5.5 备份 & 恢复模块

1. **备份导出**
   - Rust读取全部业务表：question_bank、question、tag、question_tag、answer_record（含 ai_result）、practice_session、settings、ai_analysis_cache
   - 序列化为完整JSON结构，写入自定义后缀备份文件（例如`.qpbackup`）
   - 备份包**不兼容普通CSV**；**含 API Key 明文，导出时UI提示妥善保管**
2. **备份恢复**
   1. 用户选择备份文件，前端弹出风险确认弹窗：将覆盖全部本地现有数据
   2. 用户确认后，Rust清空全部业务表，解析备份JSON批量写入数据库（事务）
   3. 异常捕获：文件损坏、格式错误，UI提示恢复失败，原有数据保持不变。

### 5.6 UI与容错

1. 大批量导入题目展示加载状态，防止界面卡死
2. 删除题库集、恢复备份，必须二次确认弹窗
3. 所有IO、数据库操作捕获异常，前端友好提示，不崩溃
4. AI 调用失败静默降级，不阻塞核心刷题流程（见第7章）

## 6. 主题与无边框沉浸式实现

### 6.1 主题方案

- **策略**：Tailwind `darkMode: 'class'` + CSS 变量双主题。
- `:root` 定义浅色变量，`.dark` 定义深色变量（颜色、边框、阴影）。
- 组件统一使用语义化变量（如 `var(--color-bg)` / `var(--color-card)` / `var(--color-text)`）或 Tailwind `dark:` 前缀，禁止散落硬编码颜色。

```css
:root {
  --color-bg: #F5F6F8; --color-card: #FFFFFF; --color-text: #1F2328;
  --color-text-secondary: #6B7280; --color-border: #E5E7EB;
  --color-primary: #3B82F6; --color-success: #16A34A; --color-danger: #DC2626;
}
.dark {
  --color-bg: #0F1115; --color-card: #1A1D24; --color-text: #E6E8EB;
  --color-text-secondary: #9CA3AF; --color-border: #2A2E37;
  --color-primary: #60A5FA; --color-success: #4ADE80; --color-danger: #F87171;
}
```

- **主题状态机**：`theme_mode ∈ {system, light, dark}`。`system` 时监听 `matchMedia('(prefers-color-scheme: dark)')` 变化实时切换。
- 主题切换 150ms 颜色过渡；Pinia 持久化到 settings（Rust 命令），启动时读取应用。

### 6.2 无边框与沉浸式

- **桌面端**：自定义标题栏（已实现 `TitleBar.vue`），`data-tauri-drag-region` 拖拽 + 最小化/最大化/关闭；标题栏配色随主题变量。侧边栏分组：主功能组（刷题、题库）、复习与数据组（错题本、收藏、统计）、系统组（备份恢复、设置，置底）。
- **移动端（Android）**：
  - 状态栏沉浸：WebView 内容延伸到状态栏（`safe-area-inset-top` 处理），状态栏图标颜色随主题（浅色主题深色图标，深色主题浅色图标）。
  - 底部导航仅非刷题页显示。
- **沉浸刷题模式**：Pinia `immersiveMode` 状态；进入刷题页时置 true（移动端隐藏顶栏与底部导航，`main` 区域去 padding），退出刷题恢复。桌面端不强制全屏，仅随主题。
- 弹窗/Toast/确认框全部双主题适配；深色下禁用纯白大色块。

## 7. AI 功能技术实现

### 7.1 总体原则

- AI 能力**默认关闭**；未配置或开关关闭时，前端不构建 AI 客户端、不发起任何网络请求。
- 所有 AI 请求由前端 JS（axios）直连发起，不经过 Rust 后端；Rust 层仅通过 `update_ai_result` 命令写回判分结果。
- 请求与响应不写日志；API Key 不出现在前端 bundle。

### 7.2 配置读取与脱敏

- `get_ai_config` 命令返回：`{ base_url, model, api_key_masked(前4后4), judge_enabled, analysis_enabled }`；`get_ai_config_full` 返回完整配置（含 Key）仅供 AI 调用时读入内存。
- `set_ai_config` 命令：仅在用户输入新 Key 时更新 Key；留空表示不修改。
- `testAiConnectionJs`（前端）：发一次最小请求验证连通性。

### 7.3 AI 判题（前端 judgeEssayJs）

**输入**：`{ content, answer, userAnswer }`（当前题目与作答）
**流程**：
1. 前端内存构建 axios 客户端（`get_ai_config_full` 读取完整配置，仅内存）。
2. 构造 `messages`（system/user，见 7.5 Prompt 模板），`response_format: {"type":"json_object"}`、`max_tokens: 300`、`thinking` 关闭。
3. 解析 `choices[0].message.content` 为 JSON，校验 `correct ∈ {0,1}`。
4. 前端展示判分与理由；调 Rust 命令 `update_ai_result(record_id, correct)` 写回 `ai_result` 并同步 `is_fault` / `fault_count`（Rust 端仅存储职责，不发起网络请求）。

**失败处理**：网络错误/超时/非JSON → 不写 `ai_result`，前端提示并回退"手动标记"模式。

### 7.4 AI 解析（前端 analyzeMistakeJs）

**输入**：`{ questionId, content, answer, userAnswer, analysis? }`
**流程**：
1. 计算作答哈希（djb2），先经 `get_ai_analysis` 查本地缓存，命中直接返回。
2. 未命中则前端 axios 调用（判错后异步触发），超时 15s；成功后经 `save_ai_analysis` 写回缓存。
3. 返回文本解析（≤120字）→ 前端展示"AI 错题解析（仅供参考）"卡片。
4. 失败 → 静默降级（仅展示题目自带解析）。

### 7.5 Prompt 模板（前端 `src/utils/ai.ts`）

**判题（essay）**

```
system: 你是严格的中文阅卷老师。请判断学生作答是否正确，
        只输出 JSON：{"correct":0或1,"reason":"不超过80字的简短理由"}
user: 题干：{content}
      参考答案：{answer}
      学生作答：{userAnswer}
```

**错题解析**

```
system: 你是耐心的刷题助教。请用中文简要说明学生错在哪里、正确思路是什么。
        120 字以内，直接输出解析文本，不要编号。
user: 题干：{content}
      参考答案：{answer}
      学生作答：{userAnswer}
      原题解析：{analysis 如有}
```

### 7.6 错误处理

|错误|判定|UI 文案|
|---|---|---|
|401|HTTP 401|API Key 无效，请到设置检查|
|402|HTTP 402|AI 账户余额不足，请充值|
|422|HTTP 422|请求参数错误（请检查模型名与 Base URL）|
|429|HTTP 429|请求过于频繁，请稍后再试|
|500/503|HTTP 500/503|AI 服务端故障/繁忙，请稍后重试|
|超时/网络错误|fetch 异常|AI 服务连接失败（带底层错误详情）|
|响应非法|非JSON/字段缺失|AI 响应异常（带原始响应片段）|

- 错误处理由前端 `src/utils/ai.ts` 统一抛出结构化中文提示；axios 原生 timeout 实现超时控制。

### 7.7 依赖与 feature

- 前端：`axios`（浏览器直连，DeepSeek 支持 CORS）
- Rust：不发起任何网络请求，不注册 HTTP 插件；仅负责数据存储与判分结果写回
- 桌面与 Android 均使用系统网络栈；Android 需 `INTERNET` 权限（已具备）。

## 9. 核心业务逻辑实现说明

### 9.1 填空题机器判分逻辑（前端TS伪代码）

```typescript
/**
 * @param userInput 用户输入
 * @param stdAnswer 原始标准答案，多答案用 ; 分割
 * @returns boolean 是否机器判定正确
 */
function judgeFillAnswer(userInput: string, stdAnswer: string): boolean {
  const input = userInput.trim()
  const stdList = stdAnswer.split(';').map(s => s.trim())
  return stdList.includes(input)
}
```

> 注意：大小写敏感；只去除首尾空格，中间空格原样比对；manual_result优先级高于该函数输出。

### 9.2 多选题判分

标准答案逗号分割，用户选项集合必须完全一致，多选、少选、错选判定错误。

- 单选：所选选项文本去除首尾空格后与标准答案完全一致即正确。
- 判断：true/false，忽略大小写与首尾空格。

### 9.3 错题规则

1. single/multi/judge机器判错 → `is_fault=1`，`fault_count +=1`
2. fill填空机器判错 → `is_fault=1`；用户手动改为正确，则`is_fault=0`
3. essay简答：AI判错（`ai_result=0`）或手动标错（`manual_result=0`）→ 错题；覆写为对则移出
4. 移出错题：仅设置`is_fault=0`，做题记录保留，不删除行。

### 9.4 最终结果计算（SQL）

```sql
COALESCE(manual_result, ai_result, machine_result) AS final_result
```

- 统计、错题本、AI 解析触发均以 `final_result = 0` 判定为错。

## 12. 风险与注意事项

1. **数据安全**：卸载App本地SQLite数据丢失，必须依赖用户手动导出`.qpbackup`备份包。
2. 备份恢复：恢复前务必弹窗提示覆盖风险；解析损坏备份文件不能清空原有库。
3. 题库文件导入：严格校验，错误行跳过，输出错误行号，不污染数据库。
4. 填空题判分：大小写敏感，业务面向技术刷题，不要自动转大小写。
5. **API Key 安全**：Key 明文存本机 SQLite，且随备份包导出；UI 必须提示风险；Key 不进入前端 bundle 与日志。
6. **网络合规**：AI 请求仅发往用户配置的 Base URL；未配置/未开启时应用必须保持零网络请求（可在代码审查中验证前端 AI 客户端构建条件）。
7. **成本控制**：AI 调用产生用户费用；必须落实解析缓存、判题单次调用、会话熔断三重保护。
8. **主题一致性**：新增组件必须同步适配双主题，禁止硬编码颜色；深色主题禁用纯白大色块。
9. 本项目 MVP 范围见业务文档第 8 章；未列入功能不开发。
