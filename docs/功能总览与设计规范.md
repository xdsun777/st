## 1. 项目概述

- **定位**：个人自用、**移动端优先**的沉浸式刷题工具（Android 为主，Windows/Linux 保留）。
- **核心承诺**：单用户、无账号、无广告、无社交；**默认纯离线**，AI 功能为可选增强（用户自备 API Key，默认关闭）。
- **技术形态**：Tauri 2 + Vue3/TypeScript + Tailwind + Pinia + SQLite（sqlx），前端不直连数据库/文件/网络，统一走 Rust Tauri Command。

## 2. 功能总览

### 2.1 已实现功能

| 模块 | 功能 |
|---|---|
| 题库管理 | CSV/Excel（.csv/.xlsx/.xls）批量导入（字段校验+错误行提示+所属题库集自动归集）；题库集新建/重命名/删除（二次确认）；单题新增/编辑/删除；标签管理（新增/删除/筛选） |
| 刷题 | 顺序/随机模式；五种题型作答；上一题/下一题；中途退出自动保存会话、再次进入可续做；刷题页收藏/取消收藏 |
| 判分 | 单选/多选/判断/填空机器判分；填空手动覆写；简答手动标记对错 |
| 错题本 | 答错自动归集（按题去重、累计做错次数）；错题复习（可标签筛选）；移出错题仅清标记 |
| 收藏 | 独立于错题；收藏列表（可标签筛选）；刷收藏题目 |
| 统计 | 总题量、总刷题量、正确/错误数、整体正确率、分题库统计 |
| 备份 | 全量导出 `.qpbackup`；恢复前二次确认，覆盖本地数据；损坏文件不破坏原库 |
| 桌面窗口 | 自定义无边框标题栏（拖拽 + 最小化/最大化/退出） |
| 容错 | 全局错误 Toast；异常兜底（errorHandler / unhandledrejection）；各页加载状态 |

### 2.2 规划中功能（待开发）

1. **移动端导航重构**：一级导航收敛为 3 Tab（刷题/题库/我的），「我的」收纳错题本、收藏、统计、备份、设置；桌面侧边栏分组
2. **主题系统**：浅色/深色/跟随系统三态切换，全组件双主题适配
3. **沉浸式刷题**：移动端刷题自动隐藏导航、状态栏沉浸（Edge-to-Edge）；桌面标题栏随主题
4. **设置页**：主题、AI Base URL / API Key / 模型名、AI 判题开关、AI 解析开关、激励文案开关、测试连接
5. **AI 判题**：essay 简答提交后 AI 判题（OpenAI 兼容协议），含失败降级与手动覆写
6. **AI 错题解析**：答错后异步生成解析，本地缓存，失败静默降级
7. **轻量激励**：连续答对轻文案、完成反馈、本地连续天数提示

账号登录、多用户、付费/会员/广告、社区/分享/排行/社交打卡、网络题库爬虫、网课直播、题目搜索、自定义组卷、单题笔记、限时刷题、薄弱点分析、增量备份、AI 判题扩展到客观题/填空题、AI 生成题目/语音/对话辅导。

## 3. 核心业务规则速查

### 3.1 题型与判分

| 类型 | 题型 | 判分方式 |
|---|---|---|
| single | 单选 | 机器判分（所选选项文本 == 答案） |
| multi | 多选 | 机器判分（选项集合完全匹配；多/少/错选均判错） |
| judge | 判断 | 机器判分（true/false，忽略大小写与首尾空格） |
| fill | 填空 | 机器判分（去首尾空格、**大小写敏感**、多答案 `;` 分隔命中其一）；可手动覆写 |
| essay | 简答 | 无机器判分；**AI 判分（可选）或手动标记** |

**填空细节**：`TCP;传输控制协议` 命中任一即对；中间空格原样比对；展示用户输入、全部参考答案、解析。

**判分结果优先级（从高到低）**：
```
manual_result（手动覆写） > ai_result（AI 判题） > machine_result（机器判分）
```

### 3.2 错题 / 收藏规则

- 客观题答错自动进错题本；填空机器判错自动进（覆写为对移出）；简答 AI 判错/手动标错进（覆写为对移出）。
- 同一题多次做错仅存一条，累计 `fault_count`。
- 移出错题仅清 `is_fault` 标记，做题记录保留。
- 修改题干/答案不清除历史记录。
- 收藏独立于错题；删除题目自动取消收藏。

### 3.3 统计口径

- 以最终结果（manual > ai > machine）计入正确/错误；essay 未判题且未手动标记不计入正确率分母。
- 删除题目级联删除做题记录，统计同步更新。

### 3.4 备份规则

- `.qpbackup` 自定义 JSON 格式，含全部业务表（题目、记录、错题、收藏、标签、设置、AI 解析缓存）。
- 恢复覆盖本地全部数据；**含 API Key 明文**，导出时提示妥善保管。

> 依据《用户体验要素》五层模型组织：战略层 → 范围层 → 结构层 → 框架层 → 表现层。信息架构为结构层重点。

| 层级 | 核心问题 | 本 App 对应内容 |
|---|---|---|
| 战略层 | 为什么做 | 产品目标、用户需求、成功指标、设计原则 |
| 范围层 | 做什么 | 功能规格、内容需求、AI 功能规格 |
| 结构层 | 结构是什么 | 交互流程、**信息架构**（导航/层级/标签体系/状态） |
| 框架层 | 布局怎么做 | 导航设计、页面模板、组件清单、沉浸式布局 |
| 表现层 | 长什么样 | 主题色板、字体图标、动效、深色约束 |

---

### 4.1 战略层

**产品目标**：打造移动端优先的沉浸式刷题工具——让用户"想刷题、认真刷题、沉浸刷题"，数据本地、无干扰、默认离线。

**用户需求（痛点 → 需求映射）**

| 痛点 | 对应需求 |
|---|---|
| 题库固化 | 自定义 CSV/Excel 导入 |
| 广告会员社交干扰 | 无广告无社交，专注界面 |
| 容易分心难坚持 | 沉浸式 + 心理暗示（克制、不打扰） |
| 简答无判分、解析不足 | 可选 AI 判题 / AI 错题解析（自备 Key） |
| 数据安全焦虑 | 本地存储 + 手动备份 |

**成功指标（仅本地统计，不上报）**：连续刷题天数、单日刷题量、错题复习完成率、正确率变化。

**设计原则（总纲）**
1. 移动优先、桌面可用；2. 默认离线、AI 可选；3. 克制激励、严禁弹窗轰炸；4. 双主题全局一致；5. **移动端一级导航 ≤ 3 项**，高频直达、低频收纳；6. 操作路径最短（打开即刷题，任何页面到刷题 ≤ 2 次点击）。

---

### 4.2 范围层

**功能规格**：见第 2 章功能总览（已实现 9 模块 + 待开发 6 项）。

**内容需求（内容模型）**

| 内容类型 | 字段 | 归属关系 |
|---|---|---|
| 题目 | 题型/题干/选项/答案/解析 | 属于 1 个题库集，关联 0..N 个标签 |
| 题库集 | 名称 | 1:N 题目 |
| 标签 | 名称（唯一） | N:M 题目 |
| 做题记录 | 作答/机器结果/AI结果/手动结果/错题标记/收藏标记/做错次数 | 属于 1 道题目 |
| 会话 | 题库集/筛选/进度/模式/题集序列 | 全局唯一活动会话 |
| 设置 | 键值对（主题/AI 配置） | 全局 |

**内容边界**：错题与收藏不是独立实体，而是做题记录上的标记；AI 解析是缓存的衍生内容（不进入题库内容模型）。

**AI 功能规格（范围层明细）**
- 接口：OpenAI 兼容 Chat Completions；配置项 Base URL / API Key / 模型名；开关：AI 判题、AI 解析。
- 测试连接：设置页提供"测试连接"按钮，发起一次最小请求验证 Key/地址/模型可用性。
- 判题：仅 essay 触发；超时 10s；输出 `{"correct":0|1,"reason":"≤80字"}`；写入 `ai_result`。
- 解析：最终判错触发；异步、≤200 字、缓存（题目ID+作答哈希）、超时 15s。
- 熔断：会话内连续失败 3 次暂停；错误分类 401/429/超时/网络/响应非法。
- 安全：Key 明文本机存储（UI 提示风险）、不进前端 bundle 与日志、仅发送答题相关数据。

### 4.3 结构层

#### 4.3.1 交互设计（关键任务流）

**主线任务：刷题**

```
进入刷题页
├─ 有上次会话 → 提示「继续刷题 / 重新开始」
├─ 无会话 → 配置（题库集 + 标签 + 顺序/随机）→ 开始刷题
└─ 刷题循环：
    作答 → 提交 → 判分/标记 → 展示答案+解析(+AI解析) → 上一题/下一题
    中途退出 → 自动保存会话 → 下次续做
```

**支线任务**

| 任务 | 流程 |
|---|---|
| 导入题库 | 题库 Tab → 选择文件(.csv/.xlsx/.xls) → 解析校验 → 错误行展示 → 确认导入 → 结果汇总 |
| 错题复习 | 通道一：刷题首页「错题复习」快捷入口；通道二：我的 → 错题本 → 标签筛选 → 「刷这些错题」→ 刷题循环 |
| 收藏刷题 | 通道一：刷题首页「收藏刷题」快捷入口；通道二：我的 → 收藏 → 标签筛选 → 「刷这些收藏」→ 刷题循环 |
| AI 判题(essay) | 提交 → AI 判题中 → 结果+理由 → 可手动覆写 |
| AI 解析(答错) | 判错 → 异步生成 → 缓存 → 展示「AI 解析」卡片 |
| 备份恢复 | 我的 → 备份恢复：导出（选路径→生成.qpbackup）/ 恢复（选文件→二次确认→覆盖导入） |

#### 4.3.2 信息架构（重点）

**一级导航（移动端 3 项）**

| 序号 | Tab | 承载内容 | 设计定位 |
|---|---|---|---|
| 1 | 刷题 | 首页 + 刷题会话（沉浸式） | 主场景，打开即见 |
| 2 | 题库 | 题库集 / 题目 / 标签 / 导入 | 内容管理 |
| 3 | 我的 | 错题本 / 收藏 / 统计 / 备份 / 设置 | 低频功能收纳 |

**导航收敛原则（核心）**
1. 移动端底部 Tab **≤ 3 项**，只保留最高频入口：刷题 > 题库 > 我的。
2. **错题、收藏不占一级 Tab**：通过双通道到达——刷题首页快捷入口（高频复习）+「我的」列表（低频管理）。
3. 统计、备份、设置属低频功能，仅收进「我的」。
4. 桌面端不受 Tab 数量约束，侧边栏分组展示全部入口（屏幕空间充足，且桌面非沉浸式主场景）。
5. 任何页面到"开始刷题"不超过 2 次点击（进入即刷原则的量化约束）。

**导航模型**
- **移动端**：底部 3 Tab（刷题 / 题库 / 我的，图标 + 短标签）；刷题沉浸模式下全部导航隐藏，系统返回键退出沉浸模式。
- **桌面端**：左侧固定侧边栏（w-56，图标 + 标题 + 副标题），按组展示：
  - 主功能组：刷题、题库
  - 复习与数据组：错题本、收藏、统计
  - 系统组：备份恢复、设置（置底）

**页面层级树（移动端）**

```
App（底部 3 Tab）
├── Tab1 刷题（首页，进入即刷）
│   ├── 会话恢复提示 / 开始刷题（主操作，大按钮）
│   ├── 快捷入口卡：错题复习（N 道错题）、收藏刷题（N 道收藏）
│   ├── 轻量概览：今日刷题数 / 连续天数
│   ├── 配置区：题库集下拉 + 标签筛选 + 顺序/随机模式
│   └── 刷题态（全屏沉浸）：顶部细进度条 + 题目卡 + 退出刷题
├── Tab2 题库
│   ├── 工具栏：新建题库集 / 导入题库 / 标签管理
│   ├── 题库集列表（选中态）
│   └── 题目列表（标签筛选 + 新增/编辑/删除）
└── Tab3 我的
    ├── 错题本（标签筛选 + 刷错题）
    ├── 收藏（标签筛选 + 刷收藏）
    ├── 统计（全局卡片 + 分题库表格）
    ├── 备份恢复（导出 / 恢复）
    └── 设置（主题 / AI 配置 / 测试连接 / 激励开关）
```

**桌面端层级**：侧边栏 7 项分组直达对应页面；「我的」内部结构在移动端为列表导航页，桌面端为独立页面直达。

**标签体系（两类）**

| 类型 | 说明 | 示例 | 可否用户管理 |
|---|---|---|---|
| 系统标签 | 题型标识，随题目类型 | 单选/多选/判断/简答/填空 | 不可删改 |
| 用户标签 | 学习分类，依附题目 | 数据库、第三章、易错 | 可增删 |

- 用户标签与题库集无关，跨题库集可用；标签筛选位置：题库、错题本、收藏、刷题配置。

**内容组织原则**
1. 题目归属：题目 ∈ 题库集（1:1）；题目 ↔ 标签（N:M）。
2. 记录归属：做题记录 ∈ 题目；错题/收藏是记录上的标记，不建独立表。
3. 会话：全局仅一份活动会话，新建覆盖旧会话。
4. 设置：键值对，全局生效。

**全局状态（Pinia）**
- 顶级视图：`刷题 / 题库 / 我的` 三态；「我的」内部子视图（错题/收藏/统计/备份/设置）作为次级路由状态。
- 其余：`practiceSource`（错题/收藏跳转刷题的来源）、`session`（会话内存态）、`toasts`（全局提示）、`themeMode`（主题，规划中）、`immersiveMode`（沉浸模式，规划中）。

**信息层级规则（页面内）**
1. 页面标题 + 一句说明（副标题）→ 2. 操作区（工具栏/筛选）→ 3. 内容区（列表/卡片）。
2. 弹窗层级：确认弹窗 > 表单弹窗 > 页面内提示 banner > Toast。
3. 同一页面主操作唯一（如刷题首页主操作是"开始刷题"、题库页主操作是"新建题库集"），次要操作弱化（描边按钮）。
4. 「我的」作为收纳页：列表项 = 图标 + 标题 + 副标题/角标（如错题本显示错题数），点击进入子页面，返回键回「我的」。

### 4.4 框架层

**导航设计**
- 桌面侧边栏：`w-56`，分组展示；每项 = 图标(20px) + 标题(14px) + 副标题(12px)；选中态 `bg-blue-50 text-blue-700`；「系统组」（备份恢复、设置）置底。
- 移动端底部 Tab：**3 列等宽**（刷题 / 题库 / 我的），图标(24px) + 短标签(11px)；选中态品牌蓝；「刷题」Tab **居首位**（首页定位）。
- 刷题沉浸模式（规划中）：移动端隐藏底部 Tab 与顶部栏，仅保留退出按钮与题目卡；系统返回键退出。
- 刷题首页结构（规划中）：从上到下依次为 ①会话恢复/开始刷题主操作 ②错题复习/收藏刷题快捷入口 ③今日概览 ④配置区。
- 「我的」页结构（规划中）：列表导航（错题本/收藏/统计/备份恢复/设置），每项带角标（错题数/收藏数）。

**页面模板**
- 列表页模板：页头（标题+说明+工具栏）→ 筛选行 → 内容列表/空状态。
- 刷题页模板：配置态（表单卡片）/ 刷题态（进度条 + 题目卡 + 底部导航按钮）。
- 结果区字段顺序：判定结果（对/错/AI判题）→ 参考答案 → 解析 → AI 错题解析（如有）→ 覆写/标记按钮（填空/简答）。

**组件清单**
- 通用：ConfirmDialog（二次确认）、TagFilter（标签筛选）、TagManager（标签管理）、TitleBar（桌面标题栏）。
- 题目：QuestionCard（五题型作答）、QuestionFormModal（单题表单）、CsvImportModal（导入弹窗）。
- 规划中：SettingsView（设置页）、AiConfigForm、ThemeSwitch。

**无边框沉浸式布局**
- 移动端：状态栏透明（safe-area）；进入刷题隐藏导航、`main` 去 padding 全屏只留题目卡；系统返回键退出沉浸模式。
- 桌面端：自定义标题栏随主题（浅色白底/深色暗底），最小化/最大化/退出 + 拖拽。

**信息设计（字段展示规范）**
- 题目卡：题型徽章 + 标签徽章 + 题干（font-medium）+ 答案/解析（次要文字）。
- 作答区：单选/多选为选项按钮列表（字母前缀 + 选项文本）；判断为对/错双按钮；填空/简答为文本框。
- 错误信息：操作失败优先页内 banner（可关闭）；全局未捕获异常走 Toast（顶部，5 秒自动消失）。

**主题规范**：三态 `跟随系统（默认）/ 浅色 / 深色`；设置页切换实时生效；持久化 settings 表。

**深色主题色板**

| 角色 | 色值 |
|---|---|
| 页面背景 | `#0F1115` |
| 卡片 | `#1A1D24` |
| 主文字 / 次要文字 | `#E6E8EB` / `#9CA3AF` |
| 品牌蓝 | `#60A5FA` |
| 答对绿 / 答错红 | `#4ADE80` / `#F87171` |

**实现约束**
- Tailwind `darkMode: 'class'` + CSS 变量（`:root` / `.dark`）；组件使用语义化变量或 `dark:` 前缀，**禁止散落硬编码颜色**。
- 深色下禁用高饱和纯白大色块；答案/解析卡片用暗色卡片 + 低饱和色边。
- 弹窗、Toast、确认框必须双主题适配；主题切换 150ms 颜色过渡。

**字体与图标**
- 字体：系统字体栈（移动端系统默认中文字体；桌面端 `-apple-system, Segoe UI, sans-serif`）。
- 图标：内联 SVG（heroicons outline 风格，stroke-width 1.5），不引入额外图标库。

**动效**
- 颜色过渡 150ms；激励文案 1.5s 淡出；弹窗淡入；列表不做过场动画（保持克制）。

**心理暗示视觉原则（表现层落地）**
1. 进度用顶部细进度条替代"第 N/M 题"数字；2. 激励文案小字号、次要色、自动淡出；3. 完成反馈居中轻卡片；4. 深色主题适配夜间。

**交互容错（跨层规范）**
- 大批量导入展示加载状态；删除题库集、恢复备份必须二次确认。
- 所有 IO/数据库操作捕获异常，友好提示，不崩溃。
- AI 调用失败静默降级，不阻塞核心刷题流程。

## 5. 数据设计规范

### 5.1 数据库表（SQLite）

| 表 | 用途 |
|---|---|
| question_bank | 题库集 |
| question | 题目（options 为 JSON 字符串；ON DELETE CASCADE） |
| tag | 标签（name 唯一） |
| question_tag | 题目-标签多对多 |
| answer_record | 做题记录（承载 machine/ai/manual 三结果、is_fault、is_collect、fault_count） |
| practice_session | 刷题会话（单条有效；tag_filter 存 JSON 含题集 id 序列） |
| settings | 键值设置（主题/AI 配置，规划中） |
| ai_analysis_cache | AI 解析缓存（question_id + answer_hash 唯一，规划中） |

- **最终结果 SQL**：`COALESCE(manual_result, ai_result, machine_result)`
- **迁移**：`ALTER TABLE answer_record ADD COLUMN ai_result INTEGER` + 新增两表，启动时幂等执行（规划中）。

### 5.2 题库文件格式（CSV / Excel）

- 支持 `.csv` / `.xlsx` / `.xls`，**字段规范完全一致**；Excel 取第一个工作表，第一行为表头，单元格按文本处理。
- CSV 建议 UTF-8；Excel 无编码设置。

| 字段 | 必填 | 说明 |
|---|---|---|
| 题目类型 | 是 | single / multi / judge / essay / fill |
| 题干 | 是 | 题目文本 |
| 选项 | 否 | 单选/多选用，英文逗号分隔（CSV 含逗号加引号；Excel 直接填单元格） |
| 正确答案 | 是 | 单选 `A`；多选 `A,B`；判断 `true/false`；填空多答案 `;` 分隔；简答填参考 |
| 解析 | 否 | 解析文本 |
| 标签 | 否 | 英文逗号分隔 |
| 所属题库集 | 否 | 按名自动创建/归集；留空归入默认题库集 |

**校验规则**：题干空/类型非法/答案空 → 跳过并报行号；判断题答案必须 true/false；重复题干保留原题；字母答案自动映射为选项文本；多选答案兼容分号。

### 5.3 备份包

- 自定义 `.qpbackup`（JSON），仅本 App 使用，不与 CSV/Excel 互通。
- 恢复覆盖本地数据（二次确认）；损坏文件不破坏原库。

## 6. 技术架构摘要

- **分层**：Vue 前端（UI/解析/判分）↔ Tauri Command ↔ Rust（SQLite/文件 IO/AI HTTP）。
- **解析**：PapaParse（CSV）+ SheetJS（Excel），共用 `validateRows` 校验，Rust 事务批量写入。
- **AI 链路**：Rust 层 reqwest（rustls）发起，Key 不暴露前端；`ai_judge` / `ai_analysis` / `test_ai_connection` 命令；会话熔断。
- **主题**：Pinia 维护 theme_mode → `dark` class + CSS 变量；system 模式监听 `prefers-color-scheme`。
- **沉浸模式**：Pinia `immersiveMode`；移动端进入刷题隐藏导航。
- **平台产物**：Windows `.exe` / Linux `.AppImage` / Android `.apk`（arm64，自用不上架）。
- **环境要求**：Node ≥ 20；Rust stable；Android 需 SDK + NDK。
